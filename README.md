# 코어 포트폴리오 일일 리포트 (GitHub Actions + Telegram)

매일 아침 06:30(KST)에 자동으로 실행되어, **코어(QQQ/TLT/GLD)** 3개 자산의
오늘자 신호값과, 확정된 운영 원칙에 따라 계산한 실제 배분 비중을 텔레그램으로
보내주는 자동화입니다.

## 적용한 운영 원칙

1. 코어(core) = QQQ, TLT, GLD / 새터라이트(satellite)는 별도(이 리포트에는
   미포함 — 전략 확정 후 추가 예정)
2. 코어 목표 비중 합계 = 전체 포트폴리오의 **80%**
3. 새터라이트는 코어에서 남는 현금 중 일부로 추후 운영 예정(최대 비중 미정)
4. 코어 내부(코어=100% 기준) 자산별 **최대 비중**: QQQ 80%, TLT 80%, GLD 40%

## 신호 → 비중 계산 방식

각 자산은 이미 프로젝트에서 검증된 독립 신호(0~100%)를 가지고 있습니다:

- **QQQ**: 20/120/200일 이동평균 개별 히스테리시스(매수 +1.0%/매도 -1.5%) →
  ON 개수(0~3) → 신호 0/33/67/100%
- **TLT**: QQQ-TLT 120일 상관계수 → 756일 백분위 → 히스테리시스(진입
  0.65/이탈 0.40) → 신호 0%/100%
- **GLD**: 기대인플레이션(T10YIE) 504일 백분위 → 4단계 계단식(경계
  [0.25,0.50,0.75], 밴드 ±0.20) → 신호 0/33/67/100%

이 신호값(0~100%)을 **자산별 코어 내부 최대비중까지 선형으로 매핑**해서
"코어 내부 비중"을 구합니다.

```
코어 내부 비중(자산) = 신호값(0~1) × 최대비중(자산)
예) QQQ 신호 100% → 코어 내부 80%(최대치)
    GLD 신호 67%  → 코어 내부 40% × 0.67 = 26.7%
```

세 자산의 코어 내부 비중 합이 100%를 넘으면(캡 합계가 80+80+40=200%이므로
자주 발생할 수 있음) **비례 축소(정규화)**해서 항상 코어 내부 합계가 100%를
넘지 않게 만듭니다. 100%가 안 되면 남는 만큼은 "코어 내 미배분 현금"으로
표시됩니다.

> ⚠️ **이 결합 방식은 하나의 해석입니다.** "자산별 최대 비중"이라는 조건만
> 가지고 가장 단순하게 도출한 선형 매핑 + 정규화 방식이며, 실제로 원하시는
> 배분 로직(예: 우선순위 기반 조정, 다른 스케일링 등)과 다르면 `core_signals.py`의
> `combine_core()` 함수만 고치면 바로 반영됩니다. 매일 리포트에 계산 근거
> (신호값, 코어 내부 비중, 정규화 여부)를 모두 보여주므로 원하시는 방식과
> 맞는지 며칠 지켜보고 조정하시면 됩니다.

## 메시지 예시

```
📊 코어 포트폴리오 신호 리포트 — 2026-09-13

● QQQ: 신호 100%  (기준일 2026-09-11, 종가 512.30)
   20일선▲ 120일선▲ 200일선▲ (신호 3/3개)
   → 코어 내부 비중 75.0% (최대 80%)  → 전체 비중 60.0%
● TLT: 신호 0%  (기준일 2026-09-11, 종가 88.10)
   QQQ-TLT상관 favorability=0.31 (진입>0.65/이탈<0.40)
   → 코어 내부 비중 0.0% (최대 80%)  → 전체 비중 0.0%
● GLD: 신호 67%  (기준일 2026-09-11, 종가 245.60)
   T10YIE=2.35%, 504일 백분위=0.71
   → 코어 내부 비중 25.0% (최대 40%)  → 전체 비중 20.0%

코어 내부 합계(정규화 전): 106.7%
⚠️ 100% 초과 → 비례 축소(정규화) 적용됨 (코어 내 현금 없음)

전체 포트폴리오 요약:
   QQQ 60.0% + TLT 0.0% + GLD 20.0% + 코어 내 현금 0.0% = 코어 합계 80%
   위성/현금 예비분: 20% (새터라이트 전략 확정 전, 전액 현금 대기)
```

## ⚠️ 참고 — 새터라이트는 아직 미포함

새터라이트 최대 비중과 종목이 아직 미확정이라 이 리포트에는 넣지 않았습니다.
확정되면 `core_signals.py`에 새터라이트 신호 계산을 추가해서 같은 리포트에
합칠 수 있습니다(기존에 SOXX/XLE/코스피200 등 개별 신호는 별도로 이미
검증되어 있어 재사용 가능).

## 설정 방법 (최초 1회)

### 1. GitHub 저장소 만들기

1. https://github.com/new 에서 새 저장소 생성 (Private 권장)
2. 이 폴더(`core-portfolio-signals/`) 안의 파일들을 그대로 저장소에 업로드:
   - `core_signals.py`
   - `requirements.txt`
   - `.github/workflows/daily_report.yml`
   - `.github/workflows/keep_alive.yml` (60일 자동 비활성화 방지 — 아래 6번 참고)
   - (이 `README.md`도 함께 올려두면 나중에 다시 볼 때 편합니다)

   git을 쓸 수 있으면:
   ```
   git init
   git add .
   git commit -m "Add core portfolio daily report automation"
   git branch -M main
   git remote add origin https://github.com/<사용자명>/<저장소명>.git
   git push -u origin main
   ```

### 2. 텔레그램 봇 만들기

1. 텔레그램에서 **@BotFather** 검색 → 대화 시작
2. `/newbot` 입력 → 봇 이름과 username(반드시 `bot`으로 끝나야 함) 입력
3. 완료되면 **API 토큰**을 줍니다 (예: `123456789:ABCdefGhIJKlmNoPQRsTUVwxyZ`)
   → 이게 `TELEGRAM_TOKEN`

### 3. 내 chat_id 알아내기

1. 방금 만든 봇을 텔레그램에서 검색해서 대화 시작 → 아무 메시지나 하나
   보내기 (예: "안녕")
2. 브라우저에서 아래 주소 접속 (TOKEN은 위에서 받은 값으로 교체):
   ```
   https://api.telegram.org/bot<TOKEN>/getUpdates
   ```
3. 응답 JSON에서 `"chat":{"id":123456789, ...}` 부분의 숫자가
   **chat_id** → 이게 `TELEGRAM_TO`

### 4. GitHub Secrets에 등록

1. 저장소 페이지 → **Settings** → **Secrets and variables** → **Actions**
2. **New repository secret** 클릭, 아래 2개를 각각 추가:
   - Name: `TELEGRAM_TOKEN` / Value: (2번에서 받은 토큰)
   - Name: `TELEGRAM_TO` / Value: (3번에서 받은 숫자)

### 5. Actions 활성화 확인 & 수동 테스트

1. 저장소 페이지 → **Actions** 탭 → 처음이면 "I understand my workflows,
   go ahead and enable them" 클릭
2. **Core Portfolio Daily Report** 워크플로 선택 → **Run workflow** 버튼
   클릭 → 즉시 1회 실행
3. 1~2분 뒤 로그 확인 + 텔레그램 메시지 도착 확인

### 6. ⚠️ 60일 비활성 시 자동 비활성화 방지 (keep_alive.yml)

GitHub은 **저장소에 60일 이상 push(커밋)가 없으면 예약된(cron) 워크플로를
자동으로 꺼버립니다.** 이 저장소는 사람이 직접 커밋할 일이 거의 없는
"셋업하고 잊어버리는" 구조라 그대로 두면 두 달쯤 뒤 아침 리포트가 조용히
끊길 수 있습니다.

이를 막기 위해 `.github/workflows/keep_alive.yml`을 함께 넣어뒀습니다 —
매달 1일 자동으로 아주 작은 파일(`.keepalive/last_ping.txt`)을 갱신해서
커밋·푸시하는 워크플로입니다. 60일보다 훨씬 짧은 주기라 저장소가 계속
"활동 중"으로 인식되어 `daily_report.yml`이 계속 살아있게 됩니다.
별도 설정 없이 저장소 업로드 시 함께 올리면 바로 작동합니다(Actions
기본 `GITHUB_TOKEN`에 쓰기 권한이 필요한데, 최신 저장소는 기본 허용되어
있고, 혹시 push가 거부되면 **Settings → Actions → General → Workflow
permissions**에서 "Read and write permissions"로 바꿔주세요).
