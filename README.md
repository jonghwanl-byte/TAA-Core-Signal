# 코어 포트폴리오 일일 신호 (QQQ · TLT · GLD · XLE) — P모델 v4

미국 종가 기준으로 이동평균 신호를 계산해 **매일 한국시간 06:30(월~토)** 텔레그램으로 목표비중을 보내 주는 저장소입니다.
매매는 사용자가 **수동**으로 합니다(신호 다음 날 한국장 오후 2시 전후 = 백테스트의 "익일 시초가 체결" 가정).

> 투자 참고용 도구입니다. 백테스트 성과는 과거 데이터 기준이며 미래 성과를 보장하지 않습니다.
> 자세한 검증 결과와 기대치는 `docs/통합정리_P모델.md` 를 보세요.

## 1. 전략 규칙 (P모델)

| 자산 | 판정 | 이평선 | 밴드 (매수 / 매도) | 방식 | 최대비중(Cap) |
|---|---|---|---|---|---|
| QQQ | 주봉 (금요일 종가) | 20 / 50 / 100 주 | +1.0% / -1.0% | C | 60% |
| TLT | 일봉 (매일) | 20 / 120 / 200 일 | +4.0% / -0.5% | C | 40% |
| GLD | 주봉 (금요일 종가) | 20 / 50 / 100 주 | +3.0% / -2.0% | C | 20% |
| XLE | 주봉 (금요일 종가) | 20 / 50 / 100 주 | +3.0% / -2.0% | A | 20% |

- **밴드(히스테리시스):** 종가 > MA × (1 + 매수밴드) 이면 ON, 종가 < MA × (1 − 매도밴드) 이면 OFF, 그 사이는 이전 상태 유지
- **방식 A:** 켜진 이평선 3 / 2 / 1 / 0개 → 100 / 75 / 50 / 0 %
- **방식 C(기존):** 켜진 개수가 늘면 +50%p, 줄면 −50%p (한 번에 ±50%p 한도), 0~100%
- **목표비중 = 신호비중 × Cap.** 합이 100%를 넘으면 비례 축소하고 나머지는 현금
- 주봉 신호는 금요일 종가로 확정되어 다음 금요일까지 유지 (TLT만 매일 재판정)
- 데이터: yfinance `auto_adjust=True` (배당 조정가)

## 3. 설치 (처음 한 번)

1. GitHub에 **비공개(Private)** 저장소를 만들고 위 파일을 **폴더 구조 그대로** 올립니다. (`.github` 폴더 이름 앞의 점 주의)
2. 텔레그램 봇 준비
   - 텔레그램에서 **@BotFather** 로 봇을 만들고 **토큰**을 받습니다.
   - 만든 봇에게 아무 메시지나 한 번 보낸 뒤, **Chat ID**(숫자)를 확인합니다. (봇이 먼저 말을 걸 수 없으므로 반드시 사용자가 먼저 메시지를 보내야 합니다)
3. 저장소 **Settings → Secrets and variables → Actions → New repository secret** 에서 두 개 등록
   - `TELEGRAM_BOT_TOKEN` : 봇 토큰
   - `TELEGRAM_CHAT_ID` : Chat ID (숫자)
4. 저장소 **Settings → Actions → General → Workflow permissions** 에서 **"Read and write permissions"** 선택 후 Save (keepalive 커밋에 필요)
5. **Actions** 탭 → `Daily Core Signal` → **Run workflow** 로 수동 실행하고 텔레그램 메시지가 오는지 확인
6. `Keep Repo Alive` 도 **Run workflow** 로 한 번 실행해 `.keepalive` 커밋이 생기는지 확인

## 4. 메시지 종류

| 요일(한국시간) | 내용 |
|---|---|
| 토요일 · 월요일 | 📊 **리밸런싱 상세** — 변경 항목(전일 대비 비중), 정규화 여부, 자산별 이평선 ON/OFF, MA 대비 이격 |
| 화~금 | 📋 **보유 현황** — 매매 없음. 단, TLT 신호가 바뀐 날은 상세 메시지로 전환 |
| 일요일 | 실행 안 함 |

- TLT 신호가 바뀌면 합계 100% 정규화 때문에 QQQ · GLD · XLE 비중도 함께 바뀔 수 있습니다(정상 동작).
- 메시지 상단에 `⚠️ 자산별 데이터 기준일 불일치` 가 나오면 데이터가 덜 갱신된 것이니 잠시 뒤 수동 재실행하세요.

## 5. 설정 상수 (`core_signals.py` 상단)

| 상수 | 기본값 | 의미 |
|---|---|---|
| `ASSET_CONFIG` | P 확정값 | 자산별 이평선·밴드·방식·Cap |
| `CORE_BUDGET` | `1.00` | 목표비중 합 상한 |
| `EXPOSURE_SCALE` | `1.0` | 총 노출 배율. `0.9` 로 바꾸면 모든 목표비중에 0.9를 곱하고 나머지는 현금 |
| `C_JUMP` | `False` | 방식 C 정의. `False` = 기존(검증된 P), `True` = 변경된 신호 개수 × 50%p (체결 지연에 더 민감) |

## 6. 문제 해결

| 증상 | 확인할 것 |
|---|---|
| 텔레그램에 `PEER_ID_INVALID` | 코드 문제가 아님. `TELEGRAM_CHAT_ID` 가 숫자 Chat ID 인지, 봇에게 먼저 메시지를 보냈는지 확인 |
| 텔레그램 발송 실패 `401` | 봇 토큰 오타. Secrets 값 다시 등록 |
| 워크플로가 안 돎 | Actions 탭에서 비활성화됐는지 확인(60일 무활동 시 발생 → `keepalive.yml` 이 예방). "Enable workflow" 클릭 |
| keepalive 실패 (`permission denied`) | 3번 설치 4단계(Read and write permissions) 확인 |
| 메시지 시각이 어긋남 | GitHub 스케줄은 수 분~수십 분 지연될 수 있음 |
| 첫 신호가 백테스트와 조금 다름 | yfinance 배당 조정 시점 차이 가능. 처음 1~2주는 실제 매매 없이 신호만 확인(페이퍼 트레이딩) |

## 7. 알려진 한계

- 큰 낙폭이 2008 · 2020 · 2022 세 번뿐인 데이터로 검증했으므로 MDD를 보장하지 못합니다.
- 신호 당일 오후 2시 매매가 어긋나 1~2일 늦어지면 MDD가 커집니다(백테스트: 1일 지연 −13.2%, 2일 지연 −14.2%).
- 현금 수익률 0% 가정, 한국 ETF 실제 체결가(iNAV·괴리율)와 환율은 반영하지 않았습니다.
